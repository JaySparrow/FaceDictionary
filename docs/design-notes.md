# FaceDictionary 设计笔记（中文）

> 这是开发过程中的方案与决策记录，按时间累积；面向使用者的说明请看仓库根目录的 `README.md`。

## 原始方案：本地加密人脸词条检索

> **目标**：给一张只含一张人脸的照片 → 自动裁剪人脸 → 与词条库所有人脸比对 → 按匹配度返回前 5 个词条。
> **v1 前提**：查询图只含 1 张人脸；该人已在词条库中（但查询图本身不一定在库里）。
> **硬性要求**：
> 1. 词条信息、人脸照片、查询照片、人脸特征都是隐私 —— **只在本地存储和运算，除本人外任何人/程序都看不到明文**。
> 2. **任何自动行为（锁定、退出、重建索引、切换模型、升级）都不能删除或损坏词条库**。
>
> **已确认的决定**
>
> | 项目 | 决定 |
> |---|---|
> | GUI | PySide6 |
> | 词条格式 | `entry.json`（加密保存） |
> | 使用范围 | 个人使用（可以用非商用许可的模型） |
> | 解锁 | 每次启动输入主密码 |
> | 自动锁定 | 空闲 5 分钟；锁定只清内存，不动磁盘数据 |
> | 查询历史 | 查询照片 + 前 5 结果加密存盘，回看时不重新计算 |
> | 查询照片加入相册 | 支持："确认并加入该词条相册" |
> | 原始文件 | 应用从不修改、移动或删除你导入的源文件，只加密保存一份副本 |
> | HEIC | v1 支持（`pillow-heif`，纯本地内存解码） |

**深色模式与解锁页（2026-11-14）**
- **跟随系统外观**：系统在浅色和深色之间切换时，应用会重新应用样式表并重画线条图标（`common.restyle`，由 `colorSchemeChanged` 触发）。原因是 Qt 的样式表和自绘图标只在应用或绘制时取一次颜色，不重做的话深色下图标是黑的、灰字和分隔线看不见。
- **外观设置**：设置里新增 Appearance（Follow system / Light / Dark），选了马上生效，Cancel 恢复原样；存在 `QSettings` 的 `appearance` 键（不涉及隐私，解锁前的界面也要用）。实现是 Qt 6.8 起的 `styleHints().setColorScheme()`，跟随系统即 `Unknown`。
- **全局“应用保持浅色”设置**：有的 Mac 在全局域里设了 `NSRequiresAquaSystemAppearance = 1`（常见的“只让菜单栏和程序坞变深色”小技巧），这时系统切到深色，应用仍是浅色。为了让“跟随系统”名副其实，启动时只对本进程把它设为 NO（`app.allow_dark_mode()`，等同于命令行参数 `-NSRequiresAquaSystemAppearance NO`），不改系统设置。启动时终端会多一行 `NSRequiresAquaSystemAppearance=NO` 的系统日志，无害。
- **颜色约定**：强调色一律取系统 `Accent`（封面环、匹配度条、拖拽提示、标记的字段）；macOS 上的 Highlight 只是文字选中色，只用于列表选中。分隔线和非活动选中用半透明中性灰。深色下只有少数颜色需要另配（`DARK_STYLE`：卡片和搜索框底色、错误红）。
- **解锁页**：去掉卡片，内容直接在窗口上，主按钮是强调色实心按钮。

**多选与批量操作（2026-11-14）**
- **多选**：词条列表、相册、历史列表和回收站都按 Mac 惯例多选：⌘ 单击加选或取消，⇧ 单击选一段，⌘A 全选（Ctrl 单击在 Mac 上是右键，不用作多选）。被搜索框筛掉的词条不算在选中里。
- **选中多个时**：词条页和历史页右侧不显示某一项，只在中间写一行灰字 “3 entries selected” / “3 searches selected”；正在输入的内容先保存。只选一个时和以前一样。刷新（撤销、添加照片等）后选中的项保持不变。
- **批量操作**：⌫ 和右键菜单对所有选中项生效，只确认一次。词条：Move N Entries to Trash、Export N Entries…（一次警告、一个文件夹，每个词条一个子文件夹）。相册：– 和 ⌫ 删除选中的照片；🚫 在选中的照片全都未用于匹配时把它们重新启用（各用最大的那张脸，找不到脸的跳过），否则全部停用。历史：Move N Records to Trash。复制（⌘C）每行一项。
- **相册拖拽**：拖动多张时它们按原顺序作为一组插入，此时没有“交换”。
- **撤销**：批量操作是**一步**（如 “Undo Delete 3 Entries”、“Undo Remove 2 Photos”），一次 ⌘Z 全部恢复，撤销后恢复的词条重新被选中。如果其中任何一项已不在回收站，这一步整体不做并说明原因，不会只恢复一部分。历史记录的删除和以前一样不进撤销历史（在回收站可恢复）。
- **文字层级**：内容一律用正文颜色（字段名、别名、标签、回收站表格的栏名，表格行 14 号），灰色只留给提示和注释（数量、时间、列表第二行、空字段的占位字、排名和分数、说明句）。这样空着的 Aliases / Tags 占位字和填了的内容也能一眼分开。
- **历史缩略图跟着选中的脸**：以前缩略图只在搜索时按最大的脸生成一次，换脸后列表的缩略图和文字、结果对不上。现在每次换脸都按选中的脸重新生成；旧版本留下的不一致缩略图在打开 History 时后台重做（每次运行只检查一次）。

**去掉编辑模式：就地编辑与连续撤销（2026-11-13）**
- **起因**：编辑模式下刷新会把人踢出编辑，所以当时刷新时跳过了重新加载，结果新加的照片和新词条的封面要等按 ✓ 才出现。去掉编辑模式后，这个问题自然消失。
- **文字就地编辑**：名字、别名、标签、字段名和字段内容平时像普通文字一样显示（单击仍可选中复制），**双击**才变成输入框；空的地方**单击**即可填写。
  - 回车、Tab 或点别处 = 保存；多行字段用 ⌘回车（单独回车是换行）；Esc = 放弃这次修改。
  - 界面上不显示操作提示，也没有悬停高亮（原有提示记录在 [in-app-hints.md](in-app-hints.md)，留作日后教程）；空的共享字段以浅灰行常驻显示（内容处为 “—”）。
  - 锁定、切换词条、切换页面前，正在输入的内容先保存。名字不能为空：回车时提示并保持输入框，点别处时恢复原名。
- **添加字段**：参照 Notion、Obsidian 和 macOS 通讯录，页面上不放按钮。右键字段区或 Edit 菜单里有 Add Field to All Entries（⇧⌘;）和 Add Field to This Entry（⌘;）。选中后在对应区域末尾原地出现一行，先输入字段名，回车（或 Tab）直接跳到内容；Esc 或名字留空则什么都不加；重名会提示。双击字段名可改名；右键字段的菜单项写明字段名（Remove “Phone”），删除共享字段仍要二次确认。共享字段与个人字段之间只用一根分隔线区分，没有个人字段时不显示这根线。
- **更安静的界面**：照片大图下面不再显示说明和状态文字，不再有底部状态栏（数量统计和模型名称去掉，准备索引的进度和文件读不出的警告移到侧边栏底部）。相册缩略图下不再写 cover / N faces，改为给第一张（封面）加一个细框。
- **删除字段**：清空字段名并回车（或点别处）即删除，共享字段先确认；右键菜单的 Remove “字段名” 仍然可用，菜单打开期间这一行有浅色底标记，菜单项在菜单关闭后才执行（避免菜单还开着时界面被重建）。
- **照片注释**：每张照片可写一段注释（照片大图下方，空时显示灰色 Note，双击或单击填写），存在加密的词条里，可撤销；导出时写进 entry.json 的 photo_notes，导入时读回。
- **添加照片更方便**：⌘O 在 Library 页面上给当前词条添加照片（其他页面仍是打开搜索照片）；可把照片从 Finder 或浏览器直接拖进相册。
- **文件对话框记住上次的文件夹**：相册和搜索各记各的，只在内存里，退出应用即忘，不写入磁盘（保持“不留痕迹”）。
- **Delete 键**：⌫ / ⌦（Edit › Delete）删除有键盘焦点的列表里选中的项，走对应删除按钮的同一流程（同样的确认）。字段没有选中状态，不映射按键，避免误删。输入框里按键仍是退格。
- **搜索页可再次打开照片**：显示查询照片后，点击照片是选人脸，不再打开文件列表；标题栏新增 +（⌘O 同效）用于打开新照片，空白时点击搜索框仍可打开。
- **照片**：+ – 🚫 常驻；拖拽排序松手即保存；新照片和封面立即出现。添加照片只在有跳过、无人脸或读不了的文件时才弹提示。
- **照片窗口换脸**：**双击**人脸框或下方缩略图才生效，单击不改任何东西（防误触）；只有一张脸且正在使用的照片不提供选择。
- **撤销 / 重做（Edit 菜单，⌘Z / ⇧⌘Z）**：按一般 Mac 应用的方式实现（`QUndoStack`）——
  - 一条历史，⌘Z 可**连续**往回撤，⇧⌘Z 往前重做；撤销后做了新修改，被撤销的那几步就不能再重做；菜单里显示具体内容，如 “Undo Add 3 Photos”。
  - 覆盖所有词条库修改：文字、添加/删除/改名字段（含共享字段：撤销删除会把字段按原 id、原位置放回，各词条的内容也回到字段里）、添加照片、删除照片（回到原来的位置）、换序、换脸、🚫、新建词条、删除词条。
  - 在其他页面按 ⌘Z 会切到 Library 并显示被撤销的那个词条；正在输入时 ⌘Z 撤销的是输入框里的打字（系统惯例）。
  - 撤销“添加照片”或“新建词条”是把它们**移到回收站**，不会直接删除（保持“除非你确认，否则绝不永久删除”）。
  - 如果某一步已经无法重放（例如回收站已被清空），会说明原因并把这一步从历史中去掉，不会只做一半。
  - 撤销历史只在内存里，**锁定或换数据库时清空**；最多 100 步；后台任务进行中或有对话框打开时按 ⌘Z 只会提示音。
  - 导入文件夹、导出、回收站的“永久删除”不进撤销历史；搜索页的确认保留它自己的 Undo 按钮。

**打包为 macOS 应用（2026-09-20 收尾）**
- **不再依赖终端**：`scripts/build_app.py` 用 PyInstaller 产出 `FaceDictionary.app`（约 300 MB，自带 Python、Qt、OpenCV 和模型），再用 dmgbuild 产出 `FaceDictionary-1.0.0.dmg`（约 148 MB）。双击即用，无终端窗口、无后台进程依赖。1.1.0 起 dmg 里只有应用、Applications 快捷方式和 `Get Started.md`（即 `docs/get-started.md`），许可证和第三方声明放进应用的 `Contents/Resources`；构建结束后删除 `build/` 和 `dist/FaceDictionary/` 这些中间产物。
- **禁网方式改进**：原先靠 `run.command` 用 `sandbox-exec` 启动。实测发现在 .app 里"重新执行自身"会破坏 LaunchServices 注册（AppleScript 无法退出应用）。改为在进程内调用系统 `sandbox_init`，内核同样拒绝所有网络系统调用，且应用在系统里仍是正常的前台应用（实测 `lsappinfo` 显示 `type="Foreground" ... sandboxed`，网络连接数 0）。
- **模型内置**：默认打包 YuNet + ArcFace-MBF + SFace（53 MB），首次启动无需联网；可选的 R50（174 MB）默认不打包。运行时仍校验 SHA-256。
- **分享考虑**：`--open-models` 只打包 Apache-2.0 的两个模型，避免转发 InsightFace 的非商用权重。
- **Gatekeeper**：本机构建的 dmg 不带 quarantine 属性，双击即可打开；他人下载后需在"系统设置 → 隐私与安全性"点一次"仍要打开"（无 Apple 开发者账号，无法公证）。
- **数据不受影响**：数据库仍在 `~/Library/Application Support/FaceDictionary/`，更换应用版本不动数据。

**只读保护、多语言与可复制（2026-09-20 续）**
- **修复**：非编辑模式下双击照片打开的窗口仍能改"用哪张脸"。现在只读窗口照常显示所有人脸框并用绿框标出正在使用的那张，但不可点击，底部提示"编辑词条（✏️）才能更换"。
- **多语言**：词条的名字、别名、标签和所有字段都可用任意文字（英文 / 中文 / 日文 …）。
  - 搜索与排序统一做 NFKC + 大小写折叠，全角与半角、大小写都能互相匹配；
  - 别名和标签的分隔符除英文逗号外，还支持中文逗号「，」、顿号「、」和分号。
- **文字可选中复制**：界面上的文字标签统一设为可选中（窗口、页面和对话框构建后统一处理）；词条列表、历史列表和回收站列表支持右键 Copy 和 ⌘C 复制当前行。

**照片拖拽与版面对齐（2026-09-20 深夜）**
- **照片拖拽重做**（自写 `PhotoGrid`）：
  - 照片始终**吸附网格、向左密排**，不会停在任意位置；
  - **两种动作**：拖到两张照片之间 = **插入**（后面的整体后移一格，其余顺序不变）；拖到某张照片上 = **交换**（只换这两张）；
  - **拖动时有提示**：插入显示蓝色竖条，交换显示蓝色半透明蒙板，避免误操作；
  - **不再自动退出编辑模式**，照片顺序和文字一样是"待保存"状态，按 ✓ 保存、↩ 还原。
- **词条排版**：别名跟在名字右侧、灰色、用 · 分隔；标签在名字下一行左对齐；字段名左对齐加粗；共享字段与个人字段之间用一条**横向分隔线**（小字标注 only in this entry）区分，取代原来的斜体；创建/修改时间移到词条最下方。
- **版面对齐**：每个页面的列顶部都用同高度的页头栏（左侧导航栏也对齐），列底部一律延伸到窗口底部。Library 的 ＋ 和 Import… 移到列表上方的横幅，列表因此延长到底部；词条的 ✏️ / Export… / 🗑 移到词条顶部。Trash 的 Restore / Delete permanently… 也移到页头。

**词条页重做与自定义字段（2026-09-20 晚）**
- **词条默认是只读页面**：名字右侧的铅笔（✏️）进入编辑页，✓ 保存、↩ 放弃。
- **文字内容完全自定义**：默认只保留 Name、Aliases、Tags，其余通过 “+ Add a field…” 自行添加，分两类：
  - **共享字段（global）**：一旦创建，数据库内所有词条都有这一栏（各自填各自的内容）；
  - **个人字段（own）**：只出现在当前词条（标签用斜体区分）。
  - 每个字段独占一行：左侧字段名、右侧输入框，**输入框随内容自动增高**（1–6 行，超出内部滚动），空字段只占一行。
  - 删除共享字段会从所有词条移除，但**有内容的词条会把该内容保留为自己的个人字段**，不丢数据。
- **照片可拖动排序**，第一张即为该词条的封面（列表里的头像），缩略图下标有 “cover”。
- **搜索采用混合方案**：搜索框默认在 Name、Aliases、Tags 和所有共享字段中做子串匹配；左侧下拉可指定只搜其中一项，新建共享字段会自动出现在下拉里。个人字段不参与搜索（按你的要求，范围是 Names、Tags 和全局信息）。
- **旧数据自动迁移**：原来的 Notes 变成名为 Notes 的共享字段，导入 entry.json 时的其他键变成个人字段。
- **搜索结果卡片**：去掉 “Open entry” 按钮，改为点击头像或名字打开词条；匹配度进度条缩短到 120 px，副标题过长时自动省略，中间的查询照片因此获得更多空间。

**界面精简（2026-09-20）**
- 去掉与快捷键或双击重复的按钮：Search 页的 “Open photo”“Paste”（改为点击空白搜索框即可选文件，快捷键 ⌘O/⌘V 不变）；相册里的 “View”（双击照片即可）。
- “Choose face” 合并进照片查看窗口：点哪张脸就立即生效，不再需要确认按钮；窗口里只剩 Close。
- 相册的操作集中到 Photos 标题行右侧三个符号：**+**（添加照片）、**–**（移到回收站）、**🚫**（不用于匹配，可再次点击恢复）。
- 不用于匹配的照片在缩略图上直接画红色禁止标志，一眼可辨。
- 其余按钮：Settings→⚙、Lock→🔒、New entry→＋（⌘N）、Delete entry→🗑、History 的“Delete this record”→🗑；Import folder / Export 保留短词（Import… / Export…），避免符号歧义。所有符号按钮都有鼠标悬停提示。

**独立数据库与密保问题（2026-09-20）**
- **数据库与应用分离**：每个数据库就是一个独立的加密文件夹，有各自的密码和各自的恢复方式。
- 解锁界面新增数据库栏：显示当前数据库的名称和路径，“Open another…”可以从最近列表选择、选择任意文件夹，或新建数据库。
- **打开前先检查格式**：会区分“空文件夹（可新建）”“不是本应用的数据库”“格式过新，需升级应用”“可正常打开”，并显示该数据库支持哪些找回方式。
- **默认打开上次用的数据库**；最近列表只记录路径（不记录内容），存在 `~/Library/Application Support/FaceDictionary/databases.json`，可一键清空。
- **密保问题取代恢复码**：新建数据库后引导设置 3 个问题，默认答对任意 2 个即可重设密码（也可选“必须全部答对”）。答案忽略大小写、空格、标点和重音，用 scrypt 派生密钥；实现方式是把数据密钥按每种可行的答案组合分别加密保存（3 个问题取 2 个 = 3 份）。
- **恢复码仍保留**为可选的第二种方式，设置页可随时生成；旧数据库（格式 1，只有恢复码）继续可用，改密码时自动升级为格式 2。
- 取舍提示：密保问题比随机恢复码更容易被熟悉你的人猜到，界面上明确建议“答案不必真实，只要你记得住”。

**多人脸选择（2026-09-19 下午）**
- 查询照片中的 **每张脸都会检索**，并各自保存前 5 结果。人脸按阅读顺序编号（先上后下、从左到右），默认显示最大的那张。
- 选择方式：**直接点击原图上的人脸框**（悬停时高亮），也可以点图片下方的人脸缩略图，或用 ←/→ 和 1–9 键。
- 切换人脸是即时的，不重新计算；历史页也能切换，并记住上次看的是哪张脸。
- **按人脸确认**：同一张合影里的不同人脸可以分别加入不同词条的相册，撤销也只影响对应的那张脸。
- 大照片会在两种分辨率下检测再合并：合影中约 37 px 的小脸检出率从约 56% 提高到 100%，每次多花约 15 ms。
- 词条库的“Choose face…”也改为在原图上点选。命令行新增 `query --face N`。
- 旧格式的历史记录会自动兼容。demo 新增 `demo/queries/group_photo.jpg`（5 人两排合影），5 张脸的第一名全部正确。

**与原方案的差异和新增项**
- 特征索引存成加密的 npz 文件（`index/<model>.enc`），没有用 SQLite。SQLite 会把明文页写到磁盘。
- 新增 **单实例锁**：同一保险库只能被一个窗口打开，避免两个窗口互相覆盖修改。
- 新增 **坏文件容错**：个别文件损坏时会跳过并在侧边栏底部提示（原先在状态栏），不会导致整个库打不开。
- 新增 **更换恢复码**：设置里输入密码即可生成新恢复码，旧恢复码随即失效。
- 新增 **后台任务会话代号**：锁定之后才送达的旧任务结果会被丢弃，不会显示在已锁定的界面里。
- 新增 **Qt 文件对话框痕迹清理**：实测 Qt 自带的对话框会把访问过的文件夹写进 `com.qtproject.plist`，每次用完都会清除这些记录。
- 已知限制：在已加载 OpenCV 的进程里用 pillow-heif **编码** HEIC 会崩溃（原生库冲突）。应用只 **解码** HEIC，不受影响；demo 脚本改用 `sips` 生成 HEIC。

## 1. 结论（TL;DR）

| 环节 | 选型 | 说明 |
|---|---|---|
| 图片解码 | Pillow + **pillow-heif** | JPEG/PNG/HEIC 统一在内存中解码，按 EXIF 方向自动旋转；不产生临时文件 |
| 人脸检测 + 5 点关键点 | **OpenCV YuNet**（232 KB） | `cv2.FaceDetectorYN` |
| 对齐裁剪 | 5 点仿射对齐 → 112×112 | ArcFace 标准模板，约 5 行代码 |
| 特征提取（默认） | **ArcFace-MBF**（`w600k_mbf.onnx`，13.6 MB，512 维） | `cv2.dnn` 直接运行 |
| 特征提取（备选） | **SFace**（38.7 MB）/ **ArcFace-R50**（~166 MB） | 可切换，用你的数据评估后定（§9） |
| 检索 | NumPy 余弦相似度 + 每个词条取最大值 → Top-5 | 1 万张脸 0.2 ms |
| 存储 | **加密保险库**（AES-256-GCM，文件名随机 UUID） | 词条、照片、缩略图、特征、查询历史全部加密（§4） |
| 防误删 | 删除只进回收站；索引可重建；锁定不碰磁盘（§5） | |
| 网络 | 运行时完全禁网（macOS 沙箱 + 进程内拦截） | 只有首次下载模型会联网 |
| GUI | **PySide6-Essentials** | 解锁、搜索、历史、词条库、回收站 |
| 运行环境 | conda env `facedict`（Python 3.12） | 已装：numpy 2.5.3、opencv-python-headless 5.0.0 |

**运行时依赖 6 个包**：`numpy`、`opencv-python-headless`、`PySide6-Essentials`、`cryptography`、`pillow`、`pillow-heif`。scrypt 用标准库 `hashlib`。

## 4. 隐私保护设计

### 4.1 威胁模型

| 要防范的 | 例子 | 对策 |
|---|---|---|
| 数据离开本机 | 依赖库偷偷联网、以后误加联网功能、iCloud 同步 | §4.2 三层禁网 + §4.3 存放位置 |
| 磁盘上的明文 | 别人用你的 Mac 打开文件夹、Spotlight/Quick Look 缓存、备份、临时文件 | §4.3 应用层加密 + 明文不落盘 |
| 运行时旁观 | 离开电脑时应用还开着 | §4.6 自动锁定 |
| 痕迹泄露 | 日志、最近打开的文件、崩溃报告 | §4.7 |
| 开发过程中泄露 | AI 助手（Claude）读到的内容会上传到 Anthropic 服务器 | §4.8 开发隔离 |
| 被篡改 | 文件被替换或损坏 | AES-GCM 认证 + 模型 SHA-256 校验 |

**不在范围内**：已拿到你 Mac 登录权限并能以 root 调试进程、或已植入恶意软件的攻击者。

### 4.2 只在本地运算：三层禁网

1. **代码层**：没有任何联网代码；模型只从本地路径加载；没有自动更新、没有遥测；依赖均无遥测。
2. **进程层**：启动第一行安装 `netguard`，把 `socket.connect / getaddrinfo` 等替换为直接报错 —— 任何 Python 代码（含依赖库）联网都会失败。
3. **系统层**：`run.command` 通过 macOS 沙箱启动（已实测可拦截 DNS/TCP/HTTPS）：
   ```
   sandbox-exec -p '(version 1)(allow default)(deny network*)' python -m facedict
   ```
   `sandbox-exec` 已被 Apple 标记为弃用但在 macOS 15 仍可用；将来失效时由第 1、2 层兜底，也可加装开源防火墙 LuLu。

唯一联网的是 **`scripts/fetch_models.py`**：首次安装时下载模型并校验 SHA-256，不涉及任何隐私数据。

### 4.3 静态加密的保险库

**位置**：`~/Library/Application Support/FaceDictionary/vault.noindex/`
- 不在桌面/文稿（避免以后开 iCloud 同步时被上传）；`.noindex` 让 Spotlight 不索引；权限 `700`。
- Time Machine 会备份这里（只有密文），同时起到数据备份作用。

**目录结构**（文件名全部是随机 UUID）：
```
vault.noindex/
├── vault.json            # 明文，只有：格式版本、scrypt 参数、salt、被加密的数据密钥。不含个人信息
├── entries/<uuid>.enc    # 加密的 entry.json（见下）
├── photos/<uuid>.enc     # 加密的照片原始字节（JPEG/PNG/HEIC 原样保存，含词条相册和查询照片）
├── thumbs/<uuid>.enc     # 加密的缩略图/人脸裁剪（加快界面，可随时重建）
├── history/<uuid>.enc    # 加密的查询记录（§6）
├── index/<model>.enc     # 加密的特征矩阵（可随时重建的缓存）
└── trash/                # 回收站：被删除的文件原样（仍是密文）移到这里，可恢复（§5）
```

**entry.json（解密后）**：
```json
{
  "id": "…", "name": "…", "aliases": [], "tags": [], "notes": "…",
  "photos": [
    {"photo_id": "…", "sha256": "…", "bbox": [], "landmarks": [],
     "source": "import | query:<history_id>", "added_at": "…"}
  ],
  "created_at": "…", "updated_at": "…"
}
```

**密钥层级**：
```
主密码 ──scrypt(n=2¹⁷, r=8, p=1, 16B salt)──► 密钥加密密钥 KEK
                                               │ AES-256-GCM 解开
                                               ▼
                               数据密钥 DEK（随机 256 bit，只在解锁期间留在内存）
                                               │
                         每个文件：AES-256-GCM，随机 12B nonce，
                         附加认证数据 = 文件类型 + UUID（防止文件被调换）
```
- 改密码只需重新加密 DEK，不用重写全部文件。
- **恢复码**：初始化时显示一次（Base32），请抄在纸上离线保存。**忘记密码又丢了恢复码 = 数据永久无法恢复**。
- 泄露面：只有文件个数和大小（能大致看出有多少人、多少张照片），不泄露内容。

**明文只在内存**：解密后直接在内存中解码显示，**任何时候都不把明文写到磁盘或临时目录**。

### 4.4 导入

- 单张添加，或批量导入（每人一个文件夹：`entry.json` + 图片）→ 加密副本存入保险库。
- **应用从不修改、移动或删除源文件**。源文件如何处理由你自己决定（它们在保险库之外，不受加密保护）。
- 按照片内容的 SHA-256 去重：同一张照片不会重复加入同一词条。

### 4.5 导出

只能手动执行，每次弹窗警告"将生成明文文件"，并让你自己选择导出位置。

### 4.6 运行时保护

- 每次启动输入主密码；输错有短暂延迟。
- **自动锁定**：空闲 **5 分钟** 或按 `⌘L` → 清空内存中的 DEK、特征矩阵、所有显示的图片 → 回到解锁界面。
  - 用实际时间判断空闲（Mac 睡眠唤醒后，只要超过 5 分钟也会立即锁定）。
  - **锁定只清内存，不读写、不删除任何磁盘文件**（有专门测试，见 M1）。
  - 锁定时如果正在写入（例如正在加入照片），先等写完再锁，避免文件写一半。
- 退出时同样清理内存。说明：Python 无法保证内存彻底清零；macOS 的交换文件是加密的，FileVault 也保护休眠镜像。

### 4.7 不留痕迹

- **日志**：默认关闭；调试日志也不记录姓名、路径、图片。
- **最近文件**：不记录最近打开的路径；`QSettings` 只存窗口大小和浅色/深色这类非敏感设置。
- **剪贴板**：支持 `⌘V` 粘贴查询图；可选"搜索后清空剪贴板"。
- **崩溃报告**：建议到 系统设置 → 隐私与安全性 → 分析与改进，关闭"共享 Mac 分析"（本机目前开启）。
- **Finder / Quick Look / Spotlight**：保险库全是密文，不会产生可读的缩略图或索引。

### 4.8 开发过程中的隔离（针对我——Claude）

1. **我不读取、不打开、不运行真实保险库**；项目 `.claude/settings.json` 加上禁止读取保险库路径的规则。
2. **我只用公开样例图和合成数据测试**，而且测试一律使用临时目录里的临时保险库。
3. 用真实数据运行应用或评估脚本时，**请在你自己的终端里运行**（不要用 Claude Code 里的 `!` 前缀，那样输出会进入对话）。
4. 评估脚本只输出汇总数字，不输出姓名、路径。
5. 以后如果用 git：保险库本来就不在仓库里，`.gitignore` 再加一层保险。

### 4.9 供应链

- `environment.yml` 锁定精确版本；包来自 conda-forge / PyPI 官方源。
- 模型文件在下载和每次加载时都校验 SHA-256，不一致就拒绝运行。

## 5. 数据安全：防误删、防损坏

| 场景 | 保证 |
|---|---|
| 自动锁定 / 退出 | 只清内存，不碰磁盘 |
| 重建索引 / 切换识别模型 | 只重写 `index/` 和 `thumbs/`（都是可重建的缓存），**不动 `entries/`、`photos/`、`history/`** |
| 删除词条 / 照片 / 历史 | 必须确认；文件原样（密文）移到 `trash/`，可在"回收站"里恢复 |
| 永久删除 | 只能在回收站里手动操作，并需要二次确认；应用不会自动清空回收站 |
| 清空整个库 | **应用不提供这个功能** |
| 写文件 | "写临时文件 → fsync → 原子替换"，断电或崩溃也不会出现写一半的文件 |
| 将来升级数据格式 | 升级前自动把整个保险库复制一份备份（密文），升级成功后也不自动删除备份 |
| 开发 / 测试 | 保险库路径可通过环境变量指定；测试代码若发现指向默认的真实保险库路径会直接拒绝运行；我不会接触真实保险库 |
| 硬件故障 | 建议保持 Time Machine 备份（备份里是密文） |

## 6. 查询历史与"加入词条相册"

### 6.1 每次查询都会保存一条历史（加密）

```json
{
  "id": "…", "time": "2026-09-19T10:30:00+08:00",
  "photo_id": "…",                         // 查询照片原始字节，加密存于 photos/
  "face": {"bbox": [], "landmarks": [], "det_score": 0.93},
  "model": "arcface_mbf", "embedding": "<512 维特征>",
  "top5": [
    {"rank": 1, "entry_id": "…", "name_snapshot": "…", "score": 0.71, "best_photo_id": "…"}
  ],
  "confirmed": {"entry_id": "…", "added_photo_id": "…", "time": "…"}   // 未确认时为 null
}
```
- 前 5 结果是**当时的快照**：回看时直接显示，不重新计算。
- 如果词条后来改了名，显示当前名字（悬停可看当时的名字）；如果词条已删除，显示当时的名字并标"已删除"。
- 历史详情页另有"用当前词条库重新搜索"按钮（可选，结果另存一条新历史）。

### 6.2 确认并加入词条相册

- 在**搜索结果卡片**或**历史详情**里，每个候选词条都有"确认是此人，加入相册"按钮。
- 操作：把查询照片**复制一份**（新 UUID，加密）加入该词条的 `photos`，标记 `source = query:<history_id>`；**直接复用已存的特征，不重新计算**，索引增量更新；历史记录标记为"已确认 → 某词条"。
- 历史和词条相册各自独立：以后删除这条历史，不影响词条相册里的照片，反之亦然。
- 按 SHA-256 去重，防止重复加入；加错了可以从词条相册移除（进回收站）。

## 7. 识别流程

```
查询图片（只在内存）
  │ Pillow / pillow-heif 解码，按 EXIF 方向旋转
  ▼
缩放到长边 ≤ 640（YuNet 适合 10–300 px 的人脸）→ YuNet 检测
  ▼
取最大的一张脸 → 坐标映射回原图
  │                                  │
  ▼                                  ▼
显示用：人脸框外扩 25% 的方形裁剪    识别用：5 点仿射对齐 → 112×112
                                     │ ArcFace-MBF → 512 维 → L2 归一化
                                     ▼
                  相似度 = M @ q     （M：库中所有人脸，解锁时解密载入内存）
                                     ▼
          每个词条得分 = 该词条所有照片中的最高相似度
                                     ▼
          前 5 个词条 + 各自最像的库图 + 分数 ──► 显示，并加密保存为历史记录
```

- 检测不到人脸：降低阈值重试一次，仍失败则提示（手动框选放到 M5）。
- 入库照片检测到多张脸：取最大的并在界面标出，请你确认。
- v1 不判断"库外的人"，但显示分数，低于阈值时标"低置信度"。

```
├── run.command                     # 双击即可：沙箱禁网启动
├── scripts/fetch_models.py         # 唯一联网的步骤：下载模型 + SHA-256 校验
├── models/                         # yunet.onnx, w600k_mbf.onnx, (sface.onnx)
├── facedict/
│   ├── __main__.py                 # 入口：先装 netguard，再启动 GUI
│   ├── netguard.py                 # 进程内禁网
│   ├── crypto.py                   # scrypt、DEK 加解密、AES-GCM 文件读写（原子写）
│   ├── vault.py                    # 保险库：词条/照片/缩略图/历史/回收站
│   ├── imageio.py                  # 内存解码 JPEG/PNG/HEIC + EXIF 旋转
│   ├── engine.py                   # 检测、对齐、特征提取（ArcFace / SFace）
│   ├── search.py                   # 相似度、按词条聚合、Top-5
│   ├── evaluate.py                 # 留一法评估（只输出汇总数字）
│   └── gui/                        # 解锁、搜索、历史、词条库、回收站、自动锁定
└── tests/                          # 只用合成数据和公开样例图，只用临时保险库
```

**GUI 页面**
- **解锁**：首次使用 → 设置主密码并显示恢复码；之后每次启动输入密码。
- **搜索**：拖入 / 打开 / `⌘V` 粘贴图片 → 显示原图（带框）和人脸裁剪 → 5 张结果卡片（最像的库图、词条名、分数条、"确认并加入相册"按钮，点击卡片进入词条详情）。
- **历史**：按时间倒序列出（缩略图、时间、第 1 名、是否已确认）；详情页显示查询照片和当时的前 5 结果，可"确认并加入相册"。
- **词条库**：词条列表（可按名字和字段搜索）+ 就地编辑的词条页 + 相册网格（标出来自查询的照片）；新建、添加照片、批量导入、导出（带警告）；所有修改可用 ⌘Z 连续撤销。
- **回收站**：查看、恢复、永久删除（二次确认）。
- 模型启动时加载一次；检测和特征计算在后台线程，界面不卡。

## 9. 精度验证（在你自己的终端运行）

`python -m facedict.evaluate`：解锁后做**留一法**评估 —— 每张库图轮流当查询图，从库里拿掉它，看正确词条是否排第 1 / 前 5。
- 只统计至少有 2 张照片的词条；分别跑 ArcFace-MBF 和 SFace（可选 R50）。
- **只输出** Top-1 / Top-5 命中率和耗时，据此选定默认模型。
- 评估是只读的：不写历史，不改词条。
